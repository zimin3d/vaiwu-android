# Архитектура: загрузка героинь (персонажей) с сервера

**Статус:** проект (архитектурное описание, без реализации).
**Связанные файлы:** `PetViewModel.kt`, `GitHubUpdateManager.kt`, `AssistantScreens.kt` (настройки), `AssetCatalogTest.kt`, `docs/ui-spec.md`.

## 1. Цель

Позволить пользователю скачивать дополнительных героинь (персонажей) с нашего сервера.
Каждый пак содержит:

- **визуальные части**: спрайты эмоций (как в `sprite_<id>_<emotion>.png`), фон/портрет, иконка;
- **все особенности героини**: имя, описание, стартовые статы, способности/особенности, реплики, настройки анимаций.

Список доступных героинь и сам пак отдаются **только** при наличии валидного API-ключа
в настройках. Если ключа нет или он не зарегистрирован — API не возвращает ни список,
ни пак (HTTP 401/403).

## 2. Ключевые решения

| Вопрос | Решение |
|---|---|
| Идентификация пользователя | API-ключ из настроек (поле `apiKey` в `AssistantSettings`). Без него — ничего. |
| Транспорт | HTTPS REST (JSON для метаданных + ZIP/архив для пака). |
| Хранение паков | Локальная директория приложения `files/heroines/<id>/` (внутреннее хранилище, не внешнее). |
| Кэш/офлайн | Скачанные героини доступны офлайн; список «доступных на сервере» — только онлайн. |
| Конвертация фона | Скачанные спрайты проходят ту же конвертацию magenta (#FF00FF) → прозрачность, что и локальные. |
| Безопасность | Проверка подписи/хэша пака; запрет пути-траверсал при распаковке. |

### 3.1. HeroineApi (сетевой слой)

- Базовый URL берётся из настроек/константы (например `https://api.vaiwu.example/heroines`).
- Заголовок `Authorization: Bearer <apiKey>` на каждом запросе.
- Методы:
  - `GET /heroines` → `List<HeroineMeta>` (только при валидном ключе; иначе 401/403).
  - `GET /heroines/{id}/pack` → бинарный архив (ZIP) + заголовок `X-Pack-Sha256`.
- Без ключа или при невалидном ключе — запрос не выполняется (или сервер возвращает 401/403 → UI показывает «ключ не зарегистрирован»).

### 3.2. HeroineDownloader

- Скачивает ZIP во временный файл (`cache/heroine_<id>.zip`).
- Проверяет SHA-256 (из заголовка или из метаданных).
- Проверяет размер (лимит, аналог `MaxApkBytes`).
- Распаковывает в `files/heroines/<id>/` с защитой от path traversal.
- Применяет конвертацию magenta → прозрачность к спрайтам.
- Атомарность: при ошибке — удаляет частично распакованную директорию.

### 3.3. HeroineStore (локальное хранилище)

- Директория: `Context.filesDir/heroines/<id>/`.
- Структура пака:
  ```
  <id>/
    meta.json          # HeroineMeta + особенности
    icon.png
    portrait.png
    sprites/
      sprite_<id>_<emotion>.png
    ... (любые доп. ассеты)
  ```
- Индекс скачанных: `heroines_index.json` (id, version, installedAt, sha256).
- Методы: `listInstalled()`, `get(id)`, `delete(id)`, `isInstalled(id)`.

### 3.4. HeroineRepository

- Объединяет онлайн-список (если ключ валиден) и локальный список.
- `refresh()` — тянет `/heroines`, маппит в `HeroineMeta` с флагом `installed`.
- `download(id)` — качает, распаковывает, обновляет индекс, уведомляет UI.
- `delete(id)` — удаляет директорию и запись из индекса.
- Состояния загрузки: `Idle / Downloading(progress) / Installed / Error`.

### 3.5. Интеграция с существующей системой персонажей

- `CharacterProfile` / онбординг: список доступных персонажей = встроенные + скачанные.
- При создании питомца (`createPet`) герой загружается из `HeroineStore` (meta + спрайты).
- Путь к спрайтам: если герой скачанный — `files/heroines/<id>/sprites/`, иначе — `assets/` (как сейчас).

## 4. Модель данных

```kotlin
data class HeroineMeta(
    val id: String,            // "vesper", "akane", ...
    val name: String,
    val title: String,         // подпись
    val description: String,
    val version: String,       // версия пака
    val sizeBytes: Long,       // размер архива
    val sha256: String,
    val previewUrl: String?,   // миниатюра (опционально)
    val features: HeroineFeatures,
)

data class HeroineFeatures(
    val baseStats: Map<String, Int>,   // стартовые статы
    val abilities: List<String>,        // особенности/способности
    val phrases: List<String>,         // реплики
    val animations: List<String>,      // имена анимаций
)

sealed interface HeroineState {
    data object NotInstalled : HeroineState
    data class Downloading(val received: Long, val total: Long) : HeroineState
    data object Installed : HeroineState
    data class Error(val message: String) : HeroineState
}
```

## 5. Безопасность

- API-ключ хранится в настройках (как сейчас `apiKey`). Без ключа запросы не отправляются.
- Сервер возвращает 401/403 при невалидном ключе → UI: «Ключ не зарегистрирован».
- Проверка SHA-256 архива перед распаковкой.
- Защита от path traversal: имена файлов в архиве проверяются (`..`, абсолютные пути отклоняются).
- Лимит размера архива (аналог `MaxApkBytes`).
- HTTPS only (как `AllowedUpdateHosts`).

## 6. UI (по ui-spec)

- Экран «Героини»: вкладка в настройках или отдельный экран.
- Список доступных (онлайн): карточка с превью, именем, размером, кнопкой «Скачать».
- Скачанные: карточка с кнопкой «Удалить».
- Без ключа: сообщение «Введите валидный ключ в настройках» + кнопка перехода в настройки.
- Прогресс загрузки на карточке.

## 7. Офлайн-поведение

- Скачанные героини доступны без сети.
- Онлайн-список не обновляется без сети; показывается кэш (если есть) с пометкой «офлайн».
- Загрузка требует сети; при ошибке — состояние `Error`, повтор через кнопку.

## 8. Версионирование паков

- `HeroineMeta.version` позволяет обновлять пак (перезапись при новой версии).
- Индекс хранит установленную версию; при `refresh()` сравнивается с серверной.

## 9. Порядок реализации (предложение)

1. `HeroineApi` + модель + тесты URL/ключей.
2. `HeroineStore` + тесты распаковки/безопасности.
3. `HeroineDownloader` (SHA-256, лимит, атомарность).
4. `HeroineRepository` + состояния.
5. UI: экран героинь + интеграция в онбординг.
6. Конвертация magenta → прозрачность для скачанных спрайтов.
7. Обновление `AssetCatalog`/пути спрайтов для скачанных героинь.

## 10. Открытые вопросы

- Формат архива: ZIP (стандарт) или собственный. ZIP — проще, есть `java.util.zip`.
- Нужен ли дельта-апдейт паков (только изменённые файлы) — на первом этапе: полная перезапись.
- Ограничение числа скачанных героинь / места на диске — на первом этапе: без ограничения, но с предупреждением.
- Серверная часть (API) — отдельная задача, вне этого репозитория.
