# Спецификация интерфейса Vaiwu

> Статус: нормативный документ. Реализация ведётся по нему.
> Обоснование и макеты — `docs/ui-redesign-plan.md`. Здесь только требования:
> что считается правильным, как это проверяется и чем рискует продукт, если
> требование нарушено.
>
> Термины «MUST» / «SHOULD» / «MAY» — как в RFC 2119.
> Приоритеты: P0 — блокирует выпуск, P1 — следующий релиз, P2 — полировка.

## 1. Область

Спецификация покрывает:

- визуальные токены (цвет, типографика, пространство, формы, движение);
- контракты переиспользуемых компонентов;
- структуру навигации и поведение Back;
- требования к экранам и их состояниям;
- тексты, числа, локализацию;
- доступность и адаптивность;
- правила проверки (тесты, ручной чек-лист, метрики).

Спецификация **не** меняет игровую механику. Любое расхождение между UI и
нативной моделью решается в пользу нативной модели: UI показывает то, что
реально произошло, и не обещает недоступных действий.

## 2. Инварианты

Их нельзя нарушать ни на одном экране.

| ID | Инвариант |
|---|---|
| I-1 | Пользователь всегда может добраться до чата, настроек и справки — независимо от состояния питомца (бодрствует, спит, болеет, умер). |
| I-2 | Любое действие ухода (кормление, мытьё, уборка, разговор, объятие, лекарство) доступно не более чем за одно нажатие с главного экрана, если оно разрешено механикой. |
| I-3 | Ни одно разрушительное действие не выполняется без подтверждения: сброс питомца, продажа предмета, выход из активного раунда, выбор персонажа при онбординге. |
| I-4 | На экране ровно один заголовок. Глобальная шапка и локальный заголовок не дублируются. |
| I-5 | Один смысл — один экран. Статы, экипировка и сумка не размазаны по нескольким независимым входам. |
| I-6 | Системное сообщение (ошибка, «не хватает монет», «сохранено») не смешивается с речью питомца. |
| I-7 | Цвет не является единственным носителем смысла: рядом с цветом всегда есть текст или иконка. |
| I-8 | Ни один интерактивный элемент не меньше 48×48 dp по зоне нажатия. |

## 3. Токены

Токены — единственный источник значений. Экран не задаёт собственные цвета,
отступы и радиусы; он использует `Theme.kt`, `Palette.kt` и `DesignTokens.kt`.

### 3.1 Цвет

| Токен | HEX | Назначение |
|---|---|---|
| `background` | `#1A1430` | фон приложения и сцен |
| `surface` | `#1E1833` | карточки, панели, top bar |
| `surfaceElevated` | `#2A2245` | диалоги, нижние листы, bottom bar |
| `surfaceVariant` | `#332A52` | неактивные вкладки, поля, дорожки статов |
| `primary` | `#D5B8FF` | главное действие, выбранный элемент |
| `onPrimary` | `#2A1845` | текст на primary |
| `primaryContainer` | `#3D2F63` | выбранная строка, чип |
| `onPrimaryContainer` | `#F5EEFF` | текст на контейнере |
| `secondary` | `#4CE3A0` | успех, здоровье, «куплено» |
| `onSecondary` | `#05291A` | текст на secondary |
| `accent` | `#FFD166` | монеты, награды, опыт |
| `onAccent` | `#2B1D00` | текст на accent |
| `danger` | `#FF6B7A` | ошибка, HP врага, болезнь, удаление |
| `onDanger` | `#2B0A0E` | текст на danger |
| `warning` | `#FFB86B` | низкая энергия, предупреждение |
| `onWarning` | `#2B1D00` | текст на warning |
| `info` | `#72D9FF` | MP, подсказки |
| `textPrimary` | `#F5EEFF` | основной текст |
| `textSecondary` | `#B9ACD9` | подписи, второстепенный текст |
| `outline` | `#7A68B0` | обводка карточек и контролов |
| `outlineMuted` | `#4A3D6B` | разделители, декоративные линии |

Проверенный контраст (WCAG 2.1):

| Пара | Отношение | Норма |
|---|---|---|
| `textPrimary` / `background` | 16.5:1 | AA+, AAA |
| `textSecondary` / `surface` | 8.1:1 | AA+, AAA |
| `textSecondary` / `surfaceVariant` | 6.3:1 | AA+ |
| `primary` / `background` | 10.8:1 | AA+ |
| `onPrimary` / `primary` | 9.2:1 | AA+ |
| `secondary` / `surface` | 10.4:1 | AA+ |
| `onSecondary` / `secondary` | 9.6:1 | AA+ |
| `accent` / `background` | 12.9:1 | AA+ |
| `onAccent` / `accent` | 11.4:1 | AA+ |
| `danger` / `background` | 6.8:1 | AA+ |
| `onDanger` / `danger` | 6.6:1 | AA+ |
| `warning` / `background` | 10.9:1 | AA+ |
| `onWarning` / `warning` | 9.6:1 | AA+ |
| `info` / `background` | 11.6:1 | AA+ |
| `outline` / `surface` | 3.6:1 | AA (non-text) |

Требования:

- **UI-TOK-01 (P0).** Текстовые пары из таблицы MUST иметь контраст ≥ 4.5:1.
  Проверка: unit-тест `DesignTokensTest`.
- **UI-TOK-02 (P0).** Обводки интерактивных элементов MUST иметь контраст
  ≥ 3:1 к своему фону. `outlineMuted` разрешён только для декоративных
  разделителей.
- **UI-TOK-03 (P1).** На одном экране не больше двух акцентных цветов
  одновременно (primary + один из secondary/accent/warning/danger).
- **UI-TOK-04 (P1).** Чистый белый `#FFFFFF` и чистый чёрный `#000000` не
  используются как текст или фон.

### 3.2 Типографика

Базовое семейство — системное (до подключения Nunito с проверенной
кириллицей). Пиксельный шрифт для заголовков не используется, пока не
подтверждена поддержка кириллицы.

| Стиль | Размер / высота | Вес | Применение |
|---|---|---|---|
| `displayLarge` | 40 / 44 | 800 | уровень, крупная награда |
| `headlineMedium` | 28 / 34 | 800 | заголовок экрана |
| `titleLarge` | 22 / 28 | 700 | заголовок секции |
| `titleMedium` | 18 / 24 | 700 | название карточки |
| `bodyLarge` | 16 / 24 | 400 | основной текст |
| `bodyMedium` | 14 / 20 | 400 | описания, подписи полей |
| `bodySmall` | 12 / 16 | 400 | вторичные пояснения |
| `labelLarge` | 14 / 20 | 600 | текст кнопок |
| `labelMedium` | 12 / 16 | 600 | числа, бейджи |
| `labelSmall` | 11 / 14 | 600 | микро-подписи, чипы |

Требования:

- **UI-TOK-05 (P0).** Размер текста MUST быть ≥ 11 sp; для основного
  текста — ≥ 14 sp.
- **UI-TOK-06 (P1).** В одном блоке не больше двух разных высот строки.
- **UI-TOK-07 (P1).** Заголовки — не длиннее двух строк; при превышении
  используется многоточие, а не обрезка по границе.
- **UI-TOK-08 (P2).** Числа в таблицах, ценах и статах используют
  табличные цифры (`FontFeatureSetting("tnum")`) после подключения шрифта.

### 3.3 Пространство и сетка

Базовая сетка — 4 dp. Разрешённые шаги: 4, 8, 12, 16, 20, 24, 32, 40.

| Токен | Значение | Назначение |
|---|---|---|
| `screenPadding` | 16 dp | горизонтальные поля экрана |
| `cardPadding` | 16 dp | внутренние поля карточки |
| `cardGap` | 12 dp | расстояние между карточками |
| `sectionGap` | 24 dp | между смысловыми секциями |
| `itemGap` | 8 dp | между строками списка |

- **UI-TOK-09 (P0).** Горизонтальные поля экрана MUST быть 16 dp на всех
  экранах без исключений.
- **UI-TOK-10 (P1).** Отступы MUST браться из токенов, а не задаваться
  литералами в экранах.

### 3.4 Формы, обводки, тени

| Токен | Значение | Применение |
|---|---|---|
| `shapeChip` | 8 dp | чипы, бейджи |
| `shapeField` | 12 dp | поля ввода, малые кнопки |
| `shapeCard` | 16 dp | карточки, секции |
| `shapeSheet` | 24 dp | нижние листы, диалоги |
| `shapePill` | 999 dp | монеты, цена, статус |

- **UI-TOK-11 (P1).** Карточки MUST иметь обводку 1 dp `outline` и не иметь
  тени. Тень разрешена только bottom bar, FAB и диалогам.

### 3.5 Размеры и зоны нажатия

| Токен | Значение |
|---|---|
| `primaryButtonHeight` | 52 dp |
| `secondaryButtonHeight` | 44 dp |
| `minTouchTarget` | 48 dp |
| `careActionHeight` | 64 dp |
| `bottomBarHeight` | 64 dp |
| `statBarHeight` | 8 dp |
| `iconSize` | 24 dp |
| `pixelIconSize` | 16 / 32 dp |

- **UI-TOK-12 (P0).** Любая зона нажатия MUST быть ≥ 48×48 dp, даже если
  визуальный элемент меньше.
- **UI-TOK-13 (P1).** Основная кнопка экрана MUST быть 52 dp высотой;
  вторичная — 44 dp.

### 3.6 Иконки

- **UI-TOK-14 (P1).** Иконки MUST быть из одного набора: пиксельные 16/32 dp
  для игровых сущностей, линейные 24 dp для навигации.
- **UI-TOK-15 (P1).** Пока индивидуальная иконка не нарисована, используется
  Material Symbols; пустых мест и текстовых заглушек вроде `♥` быть не должно.
- **UI-TOK-16 (P0).** Декоративная иконка MUST иметь `contentDescription =
  null`; иконочная кнопка без текста — осмысленную подпись.

### 3.7 Движение

- **UI-TOK-17 (P2).** Переход между экранами — fade + slide 12 dp,
  180–220 ms.
- **UI-TOK-18 (P2).** Изменение стата анимируется 300 ms; награда
  «докручивается» 400 ms.
- **UI-TOK-19 (P0).** При `animator_duration_scale = 0` анимации MUST
  отключаться, а не ускоряться.

## 4. Компоненты

Контракт компонента: назначение, параметры, состояния, размеры. Компонент
не знает о бизнес-логике; он получает данные и колбэки.

### 4.1 `VaiwuPrimaryButton`

- Параметры: `text: String`, `onClick`, `modifier`, `enabled: Boolean`.
- Высота ≥ 52 dp, радиус `shapeField`, стиль `labelLarge`.
- Состояния: обычное, нажатое, disabled (без изменения цвета текста вручную).
- **UI-CMP-01.** На экране MUST быть не больше одной primary-кнопки.

### 4.2 `VaiwuSecondaryButton`

- Высота ≥ 44 dp, обводка `outline`, текст `primary`.
- **UI-CMP-02.** Не используется для разрушительных действий.

### 4.3 `StatMeter`

- Параметры: `label`, `value: Float`, `max: Float = 100`, `modifier`.
- Показывает подпись, числовое значение и полосу 8 dp.
- Порог цвета: `< 20` — `danger`, `< 40` — `warning`, иначе — `secondary`.
- **UI-CMP-03 (P0).** Порог MUST вычисляться по шкале 0–100, а не по
  абсолютному значению в других единицах.
- **UI-CMP-04 (P0).** Значение MUST дублироваться числом (не только полосой).
- **UI-CMP-05 (P1).** TalkBack читает «Сытость 64 из 100».

### 4.4 `StatusChip`

- Параметры: `text`, `tone: StatTone`, `modifier`.
- Пилюля, фон — тон с прозрачностью 16%, обводка — 45%, текст — тон.
- **UI-CMP-06.** Статус MUST быть текстом, а не только цветной точкой.

### 4.5 `CoinChip`

- Монета + число, табличные цифры, пилюля `surfaceVariant`.
- **UI-CMP-07.** Баланс на экране магазина MUST быть виден без прокрутки.

### 4.6 `SectionCard`

- Заголовок `titleLarge`, содержимое, обводка 1 dp, радиус 16 dp.
- **UI-CMP-08.** Секции не вкладываются друг в друга глубже одного уровня.

### 4.7 `CareActionButton`

- Иконка + подпись, высота 64 dp, зона нажатия ≥ 64 dp.
- Состояния: доступно, недоступно (disabled), «в процессе».
- **UI-CMP-09.** Подпись MUST оставаться видимой при font scale 1.3.

### 4.8 `EmptyState`

- Иконка, заголовок, одна кнопка действия.
- **UI-CMP-10.** Пустое состояние MUST предлагать действие, а не только
  констатировать пустоту.

### 4.9 `ConfirmDialog`

- Заголовок-вопрос, объяснение последствий, кнопка с глаголом («Удалить»,
  «Выйти», «Продать»), кнопка отмены.
- **UI-CMP-11 (P0).** Кнопка подтверждения MUST называть действие, а не
  «ОК».

## 5. Навигация

### 5.1 Карта

```
Онбординг (нет питомца)
└── выбор персонажа → имя → «Поселить»

Вкладки
├── Дом
│   └── Магазин (детальный экран)
├── Игры
│   ├── RPS
│   ├── Мини-игра
│   └── Бой
├── Питомец (статы + экипировка + сумка)
└── Чат

Шестерёнка → Настройки
├── Звук
├── Ассистент
├── Внешний вид
├── Обновления
├── Справка
└── Данные
```

### 5.2 Требования

- **UI-NAV-01 (P0).** Bottom bar MUST присутствовать на четырёх
  верхнеуровневых вкладках.
- **UI-NAV-02 (P1).** На фокусных экранах (RPS, мини-игра, бой, магазин)
  bottom bar скрыт; возврат — стрелкой в top bar.
- **UI-NAV-03 (P0).** Back на вкладке MUST вести на «Дом», а не закрывать
  приложение.
- **UI-NAV-04 (P0).** Back во время активного раунда MUST показывать
  подтверждение «Выйти? Награда не будет начислена».
- **UI-NAV-05 (P0).** Сон и смерть MUST NOT скрывать вкладки и настройки.
- **UI-NAV-06 (P1).** Любой раздел MUST быть достижим максимум за два
  нажатия из «Дома».
- **UI-NAV-07 (P0).** Выбор персонажа MUST NOT создавать питомца до
  нажатия «Поселить».
- **UI-NAV-08 (P1).** Состояние экрана (выбранная категория магазина,
  черновик имени) MUST переживать переход вперёд-назад в рамках сессии.

## 6. Экраны

Для каждого экрана: обязательные элементы, состояния и проверяемые
требования. Макеты — в `docs/ui-redesign-plan.md`, раздел 7.

### 6.1 Онбординг

Обязательно: крупный спрайт, имя персонажа, характер, 5 характеристик,
любимая еда, поле имени (необязательное, ≤ 24 символа), кнопка «Поселить».

- **UI-ONB-01 (P0).** Выбор персонажа не меняет состояние питомца.
- **UI-ONB-02 (P1).** Пустое имя заменяется именем персонажа.
- **UI-ONB-03 (P1).** Кнопка «Поселить» disabled, пока персонаж не выбран.

### 6.2 Дом

Обязательно: сцена с фоном по времени суток, спрайт, облачко с последней
фразой питомца, статус-чипы, 4 стата, сетка действий ухода 2×3, входы в
магазин и «Питомец», top bar с именем, днём и монетами.

Состояния: бодрствует, спит, болеет, умер, нет данных (загрузка).

- **UI-HOME-01 (P0).** Фон занимает только сцену (35–45% высоты), а не весь
  экран; затемнение — градиент, а не слой 70% на всё.
- **UI-HOME-02 (P0).** Кормление MUST быть доступно одним нажатием.
- **UI-HOME-03 (P0).** При сне остаются «Разбудить» и, если болеет,
  «Дать лекарство»; вкладки доступны.
- **UI-HOME-04 (P0).** При смерти остаются вкладки, настройки, справка и
  «Начать заново».
- **UI-HOME-05 (P1).** Системные сообщения выводятся snackbar’ом над
  bottom bar, речь питомца — в облачке.
- **UI-HOME-06 (P1).** При болезни показывается баннер с лекарством.
- **UI-HOME-07 (P1).** Статы имеют цветовые пороги и числовые значения.
- **UI-HOME-08 (P2).** Долгое нажатие на стат объясняет, что на него влияет.

### 6.3 Игры

Обязательно: карточки игр 2 колонки, стоимость энергии, награда, состояние
«не хватает энергии», выбор сложности мелодии в нижнем листе.

- **UI-GAME-01 (P0).** При нехватке энергии карточки disabled и показан
  баннер с текущим значением.
- **UI-GAME-02 (P1).** Стоимость и награда — отдельные пилюли, а не текст
  в названии.
- **UI-GAME-03 (P1).** Отдельные карточки для «Приключения» и «Данжа».

### 6.4 RPS

- **UI-GAME-04 (P1).** Три варианта — карточки с иконками, не текстовые
  кнопки.
- **UI-GAME-05 (P1).** Выбор питомца визуализирован до показа результата.

### 6.5 Мини-игры

- **UI-GAME-06 (P0).** Таймер — полоса и цифры; при < 25% — `warning`.
- **UI-GAME-07 (P1).** Фаза «смотри / повторяй» обозначена текстом.
- **UI-GAME-08 (P1).** Результат — общий оверлей с наградой, «Ещё раз»,
  «Домой».
- **UI-GAME-09 (P0).** Выход до конца раунда требует подтверждения.

### 6.6 Бой

Обязательно: арена «питомец против монстра», HP/MP обоих, лог последних
2–3 строк, панель действий, оверлей результата.

- **UI-GAME-10 (P1).** Кнопка навыка disabled, если не хватает MP, и
  показывает стоимость.
- **UI-GAME-11 (P1).** Зелья открываются в нижнем листе; disabled, если
  предметов нет.
- **UI-GAME-12 (P1).** Урон и лечение показываются всплывающими числами.
- **UI-GAME-13 (P0).** «Бежать» из данжа с добычей требует подтверждения.

### 6.7 Магазин

- **UI-ECO-01 (P1).** Категории — горизонтальные чипы, не `TabRow`.
- **UI-ECO-02 (P0).** Кнопка покупки disabled, если монет не хватает;
  подпись сообщает, сколько не хватает.
- **UI-ECO-03 (P1).** Купленный товар помечается бейджем «Куплено» без
  активной кнопки.
- **UI-ECO-04 (P1).** Пустая категория показывает `EmptyState`.

### 6.8 Питомец

- **UI-ECO-05 (P0).** Статы, экипировка и сумка живут на одном экране.
- **UI-ECO-06 (P1).** Свободные очки характеристик видны и распределяются
  с экрана.
- **UI-ECO-07 (P0).** Продажа предмета требует подтверждения с ценой.

### 6.9 Чат

- **UI-AST-01 (P0).** Лента прокручивается к новому сообщению.
- **UI-AST-02 (P0).** Клавиатура не перекрывает поле ввода (`imePadding`).
- **UI-AST-03 (P1).** Есть быстрые подсказки: время, анекдот, погода,
  напоминание.
- **UI-AST-04 (P1).** Ошибка сети — snackbar с «Повторить», не сообщение
  в ленте.

### 6.10 Настройки

- **UI-AST-05 (P1).** Настройки разбиты на секции: звук, ассистент, вид,
  обновления, справка, данные.
- **UI-AST-06 (P0).** Удаление питомца требует двойного подтверждения.
- **UI-AST-07 (P1).** Технические поля (API-ключ, координаты) не стоят в
  одном списке с бытовыми настройками.
- **UI-AST-08 (P2).** Кнопка «Проверить обновление» — не главная кнопка
  экрана.

### 6.11 Справка

- **UI-AST-09 (P1).** Оглавление и раскрывающиеся карточки.
- **UI-AST-10 (P2).** Первый экран — «Что делать, если…» с пятью
  сценариями.

### 6.12 Обновления

- **UI-UPD-01 (P1).** При доступной новой версии пользователь получает список
  изменений: версия релиза, заголовок и текст заметок (`release.notes`) в
  диалоге обновления.
- **UI-UPD-02 (P2).** При отсутствии обновлений показывается сообщение «Новых
  версий нет».
- **UI-UPD-03 (P2).** Сообщение о незакрытых обновлениях отображается в
  верхней части экрана; при включённой нижней навигации (кнопки) — поднимается
  выше зоны навигации.

Реализация: `GitHubUpdateManager.kt`, `PetViewModel.kt`, `VaiwuApp.kt`
(диалог + баннер `NoUpdatesBanner`).

## 7. Тексты и числа

- **UI-CONTENT-01 (P1).** Все пользовательские строки MUST быть в
  `strings.xml`; русских литералов в Kotlin быть не должно.
- **UI-CONTENT-02 (P1).** Монеты, дни, зелья MUST использовать `plurals`:
  «1 монета», «2 монеты», «5 монет».
- **UI-CONTENT-03 (P1).** Ошибка MUST называть нехватку и действие:
  «Не хватает 12 монет», а не «Не хватает монет».
- **UI-CONTENT-04 (P1).** Числа форматируются по текущей локали; дробей —
  не больше одного знака.
- **UI-CONTENT-05 (P1).** Обращение к питомцу — в женском роде, если так
  задан персонаж; нейтральные формулировки для Kolobok.

## 8. Доступность и адаптивность

- **UI-A11Y-01 (P0).** Контраст текста ≥ 4.5:1; элементов управления ≥ 3:1.
- **UI-A11Y-02 (P0).** Поддержка font scale 1.3 и 2.0 без обрезки
  заголовков и кнопок.
- **UI-A11Y-03 (P0).** TalkBack: порядок обхода сверху вниз, статусы
  читаются со значением и шкалой.
- **UI-A11Y-04 (P1).** Landscape: главный экран — две колонки; игры и бой —
  сцена + панель.
- **UI-A11Y-05 (P1).** Планшет: контент не шире 720 dp, по центру.
- **UI-A11Y-06 (P0).** Контент не уходит под системные панели на Android 15.

## 9. Технические требования

- **UI-TECH-01 (P0).** UI-изменения не меняют нативную механику и не
  ослабляют существующие тесты.
- **UI-TECH-02 (P0).** Каждый новый чистый расчёт (порог цвета, формат
  числа, доступность действия) покрыт JVM-тестом.
- **UI-TECH-03 (P1).** `@Preview` для каждого экрана: норма, сон, болезнь,
  смерть, длинные строки, font scale 1.3.
- **UI-TECH-04 (P2).** Скриншот-тесты 5–7 ключевых экранов на 360×640 и
  412×915.
- **UI-TECH-05 (P0).** `lintDebug` и `testDebugUnitTest` проходят в CI;
  сборка release не ломается.
- **UI-TECH-06 (P1).** Стили окна (`styles.xml`) совпадают с
  `colorScheme.background`, чтобы не было шва при запуске.

## 11. Definition of Done

Требование считается реализованным, когда:

1. код использует токены и компоненты из этой спецификации;
2. есть проверка из столбца «Проверка» (тест, lint или пункт ручного
   чек-листа);
3. `lintDebug`, `testDebugUnitTest`, native host-тесты и `assembleRelease`
   зелёные в CI;
4. требование отмечено в матрице реализации (раздел 12).
