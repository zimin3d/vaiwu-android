# Проверка механик: больной питомец с низкой энергией

Отчёт о дефекте «нельзя дать лекарство, потому что меню сбрасывается в „Разбудить“» и о вытекающей из него смерти питомца.

- Код: `main` @ `63585d5` (`v0.1.2`)
- Затронутые файлы: `external/vaiwu/firmware/components/game/src/VaiwuPet.cpp`, `app/src/main/java/su/neit/vaiwu/VaiwuApp.kt`, `app/src/main/java/su/neit/vaiwu/PetViewModel.kt`, `app/src/main/cpp/native-lib.cpp`

## 1. Краткий вывод

Дефект подтверждён. Это не косметика и не «сложность игры», а отсутствие у игрока любого способа вмешаться. Сходятся три независимые причины:

1. **UI:** в состоянии `Sleeping` показывается ровно одна кнопка — «Разбудить» (`VaiwuApp.kt:328-330`). Лекарство живёт только в ветке `else` (`:363-370`).
2. **Модель:** `wake()` (`VaiwuPet.cpp:280-292`) не даёт окна бодрствования. Ближайший тик (раз в 1 с, `PetViewModel.kt:91-95`) снова усыпляет питомца, потому что `energy <= kForcedSleepEnergy = 15` (`:136-138`).
3. **Данные:** `cure()` (`:308-323`) вообще не проверяет `Sleeping` — нативная модель готова лечить спящего. Блокирует только UI.

Итог: игрок видит болезнь (`pet.isSick` рисуется над кнопками, `VaiwuApp.kt:313-318`), видит, что питомец спит, жмёт «Разбудить», интерфейс на долю секунды показывает меню и возвращается к «Разбудить». Лекарство недоступно, голод падает, питомец умирает.

## 2. Как воспроизвести

Короткий путь (самый вероятный в реальности):

1. Оставить приложение закрытым на несколько часов.
2. Открыть. `PetViewModel.onForeground()` (`:113-139`) догоняет офлайн-время, но голод ограничен снизу `OfflineDecay.MinOfflineHunger = 1.0f` (`OfflineDecay.kt:13,22-30`).
3. Питомец возвращается с `hunger ≈ 1`, низкой `energy` и, как правило, `lifeState = Sleeping`, `isSick = true`.
4. На экране: бейдж «болеет», стат-бары, одна кнопка «Разбудить».
5. Жать «Разбудить» сколько угодно.
6. Через ~4 минуты `hunger` доходит до 0 → `LifeState::Dead` (`VaiwuPet.cpp:143-146`).

Ручной путь: довести энергию до 15 и меньше (игры/время), дождаться, пока голод упадёт ниже 10 (порог болезни), — дальше то же самое.

## 3. Хронология одного цикла

Исходное состояние: `energy = 12`, `hunger = 8`, `lifeState = Sleeping`, `isSick = true`.

| Время | Событие | Состояние после |
|---|---|---|
| t=0.0 | Игрок жмёт «Разбудить» → `wake()` | `Awake`, `happiness -= 3` |
| t=0.0 | `refreshPet()` перерисовывает экран | Меню с кормлением/лекарством видно |
| t≤1.0 | Тик: `applyDecay(1/60)` → `energy = 11.98` | `11.98 <= 15` → снова `Sleeping` |
| t≤1.0 | `refreshDerivedState()` | `isSick` остаётся `true` (голод 7.99) |
| t≤1.0 | Перерисовка | Опять только «Разбудить» |
| t+4 мин | Сон: голод −0.25/мин (половина от 0.5) | `hunger = 8 - 1 = 7` … |
| t+32 мин | … | `hunger = 0` → `Dead` |

Окно, в которое теоретически можно успеть нажать «Покормить», — меньше одной секунды и только если палец уже лежит на нужной кнопке. Практически его нет.

Обратите внимание на парадокс: `OfflineDecay` специально не даёт питомцу умереть, пока приложение закрыто (комментарий `OfflineDecay.kt:8-9`: «a pet left alone for a few hours could otherwise starve to death»). Но на первом же внутриигровом тике это ограничение обнуляется, потому что разбудить и покормить больного спящего питомца нельзя. Защита офлайна существует, а защиты онлайна нет.

## 4. Разбор по слоям

### 4.1 Нативная модель: принудительный сон без гистерезиса

```cpp
// VaiwuPet.cpp:136-138
if (stats_.energy <= kForcedSleepEnergy) {
    life_ = LifeState::Sleeping;
}
```

`kForcedSleepEnergy = 15.0f` (`:18`). Проверка стоит в `applyDecay()`, то есть выполняется на каждом тике. Выход из сна возможен только двумя путями:

- `applyDecay()` при `energy >= 100` (`:116-118`) — то есть «проспаться до конца»;
- `wake()` вручную (`:280-292`).

Но `wake()` не меняет энергию и не ставит никакой флаг «недавно разбудили». Поэтому при `energy <= 15` ручное пробуждение живёт ровно до следующего тика. Это классическая ошибка: порог входа в состояние есть, порога выхода/гистерезиса нет.

### 4.2 UI: лекарство спрятано в ветке `else`

```kotlin
// VaiwuApp.kt:326-371
when (pet.lifeState) {
    LifeState.Dead -> Button(onClick = onReset) { Text(stringResource(R.string.start_over)) }
    LifeState.Sleeping -> Button(onClick = { onAction(PetAction.Wake) }) {
        Text(stringResource(R.string.wake_up))
    }
    else -> {
        ...
        if (pet.isSick) { Button(onClick = { onAction(PetAction.Medicine) }) { ... } }
    }
}
```

`pet.isSick` рисуется **до** `when` (`:313-318`), поэтому противоречие видно прямо на экране: «болеет» написано, а кнопки лечения нет.

Отдельно: `HelpScreen` обещает «болезнь лечится лекарством» (`AssistantScreens.kt:157`). Это прямая ложь интерфейса в состоянии `Sleeping`.

### 4.3 JNI/ViewModel: успех не проверяется

```cpp
// native-lib.cpp:150-152
case 5:
    p->wake();
    return 0;   // bool проигнорирован
```

```kotlin
// PetViewModel.kt:497-499
action == PetAction.Wake && result == ActionResult.Ok -> "Пора вставать!"
action == PetAction.Medicine -> "Лекарство принято"
```

Обе ветки не смотрят на фактическое состояние. «Пора вставать!» показывается всегда, «Лекарство принято» — даже если `cure()` ничего не сделал (питомец не болен или уже мёртв). Это скрывает дефект от игрока и от разработчика.

## 5. Почему это неправильно

- **Нарушено обещание офлайн-защиты.** Игрок не наказывается за то, что закрыл приложение, но наказывается за то, что открыл его.
- **Нет агентности.** У смерти нет контрпримерного действия: любая последовательность нажатий ведёт к одному результату. В тамагочи смерть должна быть следствием пренебрежения, а не отсутствия доступной кнопки.
- **Противоречие внутри UI.** Бейдж «болеет» + подсказка «болезнь лечится лекарством» + отсутствие лекарства.
- **Ложное подтверждение.** «Пора вставать!» убеждает игрока, что он что-то сделал.
- **Необратимость.** Смерть в этой модели окончательная (`resetPet()` = новый питомец), поэтому цена дефекта максимальная.

## 6. Смежные дефекты, найденные при проверке

### 6.1 Кормление и лакомство тоже заблокированы во сне

`feed()` (`:178-195`) и `treat()` (`:267-278`) возвращают `RefusedSleeping`. Само по себе это разумно, но в сочетании с неработающим `wake()` означает, что голодного спящего питомца нельзя накормить вообще. Именно поэтому дефект смертельный, а не просто неприятный.

### 6.2 Пробуждение не сообщает о неудаче

`wake()` возвращает `bool`, JNI его теряет. Если питомец не спит, кнопка всё равно рапортует об успехе.

### 6.3 Вход в игру/бой на энергии 20–23 сжигает 8 единиц без возврата

`startPlay()` (`:197-213`) требует `energy >= 20`, сразу списывает 8 и при `energy <= 15` усыпляет. `startMiniGame` (`PetViewModel.kt:265-277`) и `startBattle` (`:307-323`) замечают, что питомец не `Awake`, отменяют сессию… но `nativeCancelPlay` (`native-lib.cpp:376-380`) сбрасывает только `rpsStarted`. Энергия не возвращается. Игрок платит 8 энергии за сообщение «Она слишком устала».

Это тот же класс ошибки: переход состояния происходит до проверки, а откат неполный.

## 7. Матрица доступных действий

### Сейчас

| Состояние | Энергия | Болен | Доступно |
|---|---|---|---|
| Awake | любая | нет | кормить, играть, мыть, говорить, убрать, обнять, магазин, чат, настройки |
| Awake | любая | да | то же + лекарство |
| Sleeping | любая | нет | разбудить |
| Sleeping | любая | да | разбудить |
| Sleeping | ≤15 | да | разбудить (не работает) + смерть |
| Dead | — | — | начать заново |

### Целевое поведение

| Состояние | Энергия | Болен | Доступно |
|---|---|---|---|
| Awake | любая | нет | как сейчас |
| Awake | любая | да | как сейчас + лекарство |
| Sleeping | любая | нет | разбудить, **покормить** (опционально) |
| Sleeping | любая | да | разбудить, **лекарство**, **покормить** (опционально) |
| Sleeping | ≤15 | да | разбудить → **гарантированное окно бодрствования ≥ 60 с** → лекарство/кормление |
| Dead | — | — | начать заново |

Главное требование: из любого состояния, кроме `Dead`, должен существовать хотя бы один путь к спасению, и он должен быть виден на экране.

## 8. Варианты исправления

### Вариант A (минимальный, только Kotlin)

Показывать кнопку лекарства и во сне:

```kotlin
LifeState.Sleeping -> Column {
    Button(onClick = { onAction(PetAction.Wake) }) { Text(stringResource(R.string.wake_up)) }
    if (pet.isSick) {
        Button(onClick = { onAction(PetAction.Medicine) }) { Text(stringResource(R.string.give_medicine)) }
    }
}
```

- Плюсы: 10 строк, не трогает сабмодуль, немедленно убирает смертность (лечение поднимает голод до порога+20, `VaiwuPet.cpp:315-317`).
- Минусы: «Разбудить» по-прежнему выглядит сломанным; кормление недоступно; причина (отсутствие гистерезиса) остаётся.

### Вариант B (минимальный, только native)

Дать `wake()` окно бодрствования:

```cpp
// в классе
float wakeGraceMinutes_{0.0f};
static constexpr float kWakeGraceMinutes = 2.0f;

bool VaiwuPet::wake()
{
    if (life_ != LifeState::Sleeping) return false;
    life_ = LifeState::Awake;
    wakeGraceMinutes_ = kWakeGraceMinutes;
    if (stats_.energy < 80.0f) stats_.happiness = clamp01(stats_.happiness - 3.0f);
    dirty_ = true;
    return true;
}

// в applyDecay(), перед проверкой принудительного сна
if (wakeGraceMinutes_ > 0.0f) {
    wakeGraceMinutes_ = std::max(0.0f, wakeGraceMinutes_ - minutes);
} else if (stats_.energy <= kForcedSleepEnergy) {
    life_ = LifeState::Sleeping;
}
```

- Плюсы: «Разбудить» начинает работать как задумано; у игрока есть 2 минуты, чтобы накормить/вылечить.
- Минусы: требует коммита в сабмодуль `external/vaiwu` и обновления указателя; не помогает, если игрок не понял, что нужно делать.

### Вариант C (рекомендуемый: A + B + явный результат wake)

1. **Native:** гистерезис из варианта B.
2. **Native:** `nativeAction(Wake)` возвращает результат `wake()` вместо безусловного `0`; в `PetViewModel` сообщение «Пора вставать!» показывается только при `result == Ok && lifeState == Awake`.
3. **UI:** лекарство доступно и во сне (вариант A). Дополнительно во сне показывать «Покормить», если `hunger < 20`, — это делает спасение очевидным.
4. **Native:** `cure()` разрешён во сне (уже так и есть) — зафиксировать это тестом, чтобы не «починили» случайно.
5. **Native:** при отмене игры/боя возвращать списанную энергию, либо проверять `energy - 8 > kForcedSleepEnergy` **до** списания.

Вариант C закрывает и симптом, и причину, и смежные дефекты 6.2–6.3.

### Чего делать не стоит

- Поднимать `kForcedSleepEnergy` — сделает хуже.
- Телепортировать энергию при пробуждении — ломает баланс и симуляцию.
- Разрешать `feed()`/`treat()` во сне без разбора — конфликтует с задумкой «не буди», лучше явное пробуждение с гарантированным окном.

## 9. План патча

### 9.1 Сабмодуль `external/vaiwu`

1. `VaiwuPet.hpp`: приватное поле `float wakeGraceMinutes_{0.0f};` и константа `kWakeGraceMinutes`.
2. `VaiwuPet.cpp`:
   - `wake()` выставляет `wakeGraceMinutes_`;
   - `applyDecay()` уменьшает счётчик и пропускает принудительный сон, пока он > 0;
   - `startPlay()` проверяет, что после списания энергии питомец останется `Awake`, иначе возвращает `TooTired` **без** списания.
3. Сериализация: `wakeGraceMinutes_` **не** сохранять (после перезапуска пусть снова спит) — иначе можно накопить окно.
4. Коммит в `zimin3d/vaiwu`, обновление указателя сабмодуля в этом репозитории.

### 9.2 Android

1. `VaiwuApp.kt:326-330`: ветка `Sleeping` → колонка с «Разбудить» и, при `pet.isSick`, «Дать лекарство».
2. `PetViewModel.kt:497-499`: проверять `result` и `_snapshot.value?.lifeState` перед сообщениями об успехе.
3. `native-lib.cpp:150-152`: возвращать `static_cast<jint>(p->wake() ? ActionResult::Ok : ActionResult::RefusedSleeping)`.
4. `GamesScreen`/`HelpScreen`: текст «8 энергии» — вынести в константу `PetAction`/`GameConstants`, чтобы совпадал с native.

### 9.3 Тесты (обязательно)

В `app/src/test/cpp/test_android_native.cpp` (host, без Android):

### 9.4 Критерии приёмки

1. Питомец в состоянии `Sleeping` + `isSick` показывает кнопку лекарства.
2. После нажатия «Разбудить» при `energy <= 15` питомец остаётся `Awake` минимум 60 секунд игрового времени.
3. `feed()` доступен в этом окне и возвращает `Ok`.
4. Больной спящий питомец с голодом 1 не умирает, если игрок взаимодействует.
5. `nativeAction(Wake)` возвращает `Ok` только при фактическом пробуждении.
6. Вход в игру при энергии 20–23 не списывает энергию, если сессия отменяется.
7. Все существующие host-тесты и Android-тесты зелёные; новые тесты падают на коде до патча и проходят после.

## 10. Оценка

- Вариант A: ~15 минут, только Kotlin, убирает смертность, но не чинит «Разбудить».
- Вариант B: ~1 час + коммит в сабмодуль, чинит причину, но оставляет UI без лекарства во сне.
- Вариант C: ~3–4 часа с тестами и CI, закрывает весь класс дефектов.

Рекомендуется C. Если нужен быстрый хотфикс — A, затем B отдельным релизом.
